§1

Überblick

Die Auslagen-Verwaltung ist eine kleine Webanwendung, mit der Vereinsmitglieder ihre verauslagten Beträge (mit Belegfoto) einreichen und der Kassenwart sie prüft, auszahlt und die Vereinskasse führt. Sie ersetzt die frühere Zettel- und Tabellen-Lösung.

Technik in einem Satz

Ein einzelner Node.js-Server (server.js, Express) liefert eine Single-Page-App aus reinem HTML/JavaScript aus (public/index.html, Tailwind per CDN) und speichert alles in einer SQLite-Datei (auslagen.db). Kein Build-Schritt, keine weiteren Dienste.

Laufzeit
Node.js, Express 4, sqlite3
Port
3000 (http://localhost:3000)
Server-Prozess
pm2-Prozess auslagen-v2 auf einem Raspberry Pi
Datenbank
SQLite-Datei neben server.js, wird beim ersten Start selbst angelegt
Sicherung
nächtlicher Cron-Job → lokale .db-Kopie + Upload nach Google Drive (rclone)
Anmeldung
Benutzername; Passwort nur für den Kassenwart

Die zwei Rollen

  • Mitglied — reicht eigene Auslagen ein, sieht und bearbeitet nur die eigenen, solange sie „offen“ sind.
  • Kassenwart — sieht alles, zahlt aus, bucht Einzahlungen, verwaltet Mitglieder, Kategorien und Backups und macht den Kassensturz.
§2

Der Server unterscheidet die Rollen über zwei Wächter: requireAuth (gültige Sitzung nötig) und requireKassenwart (Rolle muss kassenwart sein). Einige Rechte werden zusätzlich nur im Browser durchgesetzt — siehe §11.

Gut zu wissen

Das Sicherungsskript backup-auslagen.sh und der rclone-Remote gdrive: liegen nur auf dem Pi, nicht im Repository. Die Pfade /home/pi/backups/ sind in server.js fest verdrahtet — deshalb funktionieren Cloud-Export und Kassensturz-Upload nur dort, nicht lokal.

§6

Funktionen für Mitglieder

Meine Auslagen

Startansicht für Mitglieder. Drei Kacheln (Offen / Bezahlt / Anzahl) und darunter die eigenen Einträge, neueste zuerst. Belegfotos werden als Vorschau gezeigt und öffnen per Klick die Großansicht. Bei „offenen“ Einträgen erscheinen Bearbeiten und Löschen.

Neue Auslage

Formular mit Betrag, Datum, Kategorie, Zweck und Belegfotos. Fotos werden im Browser auf max. 800 px Breite verkleinert und als JPEG (Qualität 0,7) gespeichert — das hält die Datenbank klein. Mehrere Fotos pro Auslage sind möglich. Ein negativer Betrag löst eine Rückfrage-Warnung aus, ist aber erlaubt (z. B. für Rückzahlungen).

Bearbeiten

Nur eigene Auslagen und nur solange „offen“. Jede geänderte Zeile (Betrag, Datum, Zweck, Kategorie) wird mit Vorher/Nachher in die historie geschrieben und ist später im Bearbeiten-Dialog als Änderungs­protokoll sichtbar.

Löschen

Kein echtes Löschen: Der Eintrag bekommt geloescht = 1 und verschwindet aus der Mitglieder-Ansicht. Der Kassenwart sieht ihn weiterhin (durchgestrichen, mit Löschdatum). Mitglieder können nur eigene „offene“ Auslagen löschen.

§7

Funktionen für den Kassenwart

Dashboard

Drei anklickbare Kennzahl-Kacheln (Offen / Bezahlt / Anzahl aktiver Auslagen) öffnen je eine Aufschlüsselung nach Mitglied. Darunter zwei Kassen-Kacheln (siehe §8), die Tabelle „Auszahlungen je Mitglied“, optional das Einzahlungs­protokoll und schließlich „Alle Auslagen“ mit Filtern nach Mitglied, Status (inkl. gelöscht) und Kategorie.

Auszahlen

In „Auszahlungen je Mitglied“ auf eine Zeile klicken → Dialog mit allen offenen Belegen dieses Mitglieds. Gewünschte auswählen, Summe wird live berechnet, „Bezahlen“ setzt alle ausgewählten in einem Rutsch auf bezahlt. Alternativ direkt in der großen Tabelle oder in der Beleg-Großansicht.

Auslage für ein Mitglied erfassen

Wie das Mitglieder-Formular, zusätzlich mit Auswahl des Mitglieds. Fotos werden hier auf max. 1200 px verkleinert.

Massenerfassung

Ein Betrag/Zweck/Datum/Kategorie für viele Mitglieder gleichzeitig (z. B. Jahresbeitrag als negative Auslage). Alle Mitglieder sind vorausgewählt, einzeln ab­wählbar. Legt pro Mitglied eine Auslage an.

Reports

Auswertung nach Kategorie, Mitglied, Monat oder Status für einen Zeitraum (Standard: 1. Januar des Jahres bis heute). Aufklappbare Zeilen zeigen die Einzelbelege, Balken den Anteil. Export als CSV (Semikolon-getrennt) direkt aus dem Browser — die Daten kommen aus den bereits geladenen Auslagen, kein Server-Aufruf.

Kategorien verwalten

Hinzufügen und Löschen. Eine Kategorie, die noch von einer Auslage benutzt wird, lässt sich nicht löschen.

Einzahlung erfassen

Mitglied, Betrag (> 0), Datum, Zweck. Der Betrag wird ins Protokoll geschrieben und sofort auf kassenbestand addiert.

Nutzerverwaltung

Mitglieder anlegen (Benutzername + Name), sperren/entsperren, löschen. Sperren und Löschen kappen laufende Sitzungen. Der Benutzername kassenwart ist reserviert.

Sicherung & Import

  • Cloud Backup (Google Drive) — schreibt ein CSV nach /home/pi/backups/ und lädt es per rclone nach gdrive:Auslagen-Backup/Exporte. Nur auf dem Pi.
  • Lokales Backup (CSV) — lädt sofort eine CSV-Datei im Browser herunter, ohne Server.
  • CSV importieren — Datei einlesen, Vorschau­tabelle, Zeilen auswählen, importieren. Erwartet die Spaltenfolge des CSV-Exports; Zeilen ohne Mitglied oder mit Betrag ≤ 0 werden übersprungen.
§8

Kassenbestand-Berechnung

Betriebshinweis

Weil bezahlte Auslagen vom gespeicherten kassenbestand abgezogen werden, muss beim Kassensturz der tatsächlich gezählte Kassenstand eingetragen werden — nicht der auf dem Dashboard angezeigte. Danach ist die Liste leer und beide Werte sind wieder gleich.

§9

Kassensturz

Der Kassensturz schließt eine Abrechnungs­periode ab: Er sichert den aktuellen Stand und leert danach die Auslagen- und Einzahlungs­tabellen, damit die nächste Periode bei null beginnt.

Achtung

Der Kassensturz löscht alle Auslagen und Einzahlungen endgültig — auch noch offene. Die App warnt, wenn offene Auslagen existieren, und verlangt eine Bestätigung. Vor einem Kassensturz sicherstellen, dass ein aktuelles .db-Backup existiert und der rclone-Upload funktioniert (rclone lsd gdrive:Auslagen-Backup).

§10

Datensicherung & Betrieb

Deployment

Änderungen kommen über Git auf den Pi. Dort:

./deploy.sh  →  git pull origin main · npm install --omit=dev · pm2 restart auslagen-v2 · pm2 status

Der Neustart meldet alle Nutzer ab (siehe §5).

rclone-Token erneuern

Wenn der Drive-Upload invalid_grant: maybe token expired meldet:

  • Auf dem Pi: rclone config reconnect gdrive:
  • Ohne Browser auf dem Pi: den ausgegebenen Befehl rclone authorize "drive" "…" auf einem Rechner mit Browser ausführen, Google autorisieren, das ausgegebene Token bei config_token> einfügen.
  • Prüfen: rclone lsd gdrive:Auslagen-Backup

Wiederherstellung

Server stoppen, gewünschte Sicherung als auslagen.db neben server.js legen, Server starten. Fehlende Tabellen (z. B. einzahlungen in alten Backups) und Soft-Delete-Spalten werden beim Start automatisch ergänzt.

rclone-Standard-ClientGoogle entzieht dem geteilten rclone-Client gelegentlich das Token — der Upload muss dann neu autorisiert werden.
Eine SD-KarteFällt sie aus, sind nur die Google-Drive-Kopien übrig. Der Upload muss also laufen.
Obergrenze Upload-Größeexpress.json({ limit: '20mb' }) — sehr viele oder große Fotos in einer Auslage können abgewiesen werden.
